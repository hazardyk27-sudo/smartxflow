---
name: JS minify workflow and regex-edit risk
description: app.js/ui.js/inline.js are minified from .src files via minify.py; automated regex replacements on .src files must be syntax-checked before minifying/deploying.
---

This project's frontend JS (`static/js/app.js`, `ui.js`, `inline.js`) is generated by `python3 minify.py` from canonical `.src` files (`app.js.src`, `inline.js.src`). Never hand-edit the minified output directly.

**Why:** A bulk regex substitution across `app.js.src` (replacing repeated `_t('app.j.ms'+N)` calls with a helper) left a malformed function body and stray extra closing parens at ~15 call sites. The minifier ran without complaint (it doesn't validate JS syntax), the site kept running short-term at first because browsers cache scripts, but the moment the new file loaded it broke `app.js` parsing entirely — the whole app went blank/stuck on "Loading..." with zero visible errors in the agent's own smoke screenshots. It looked like "nothing changed" to the user because nothing rendered at all.

**How to apply:** After any multi-file-or-multi-line regex/sed edit to a `.src` file (not just simple single-line replacements), run `node --check <file>` on the edited `.src` AND on the generated output before restarting the workflow or pushing to Hetzner/GitHub. `node --check` cannot parse `.src` extension directly — copy/rename to `.js` temporarily or check the generated `.js` output instead.
